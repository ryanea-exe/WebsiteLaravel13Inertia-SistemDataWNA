# Database Design — Sistem Data WNA Kanim Ponorogo

## 1. Konvensi
- DBMS: MySQL dengan storage engine InnoDB dan charset `utf8mb4`.
- Semua tabel utama memakai `id` unsigned bigint auto-increment serta `created_at` dan `updated_at`, kecuali ada alasan eksplisit untuk berbeda.
- Nama tabel dan kolom snake_case.
- Password selalu disimpan sebagai hash Laravel, bukan plaintext.
- Gunakan `DATE` untuk tanggal kalender, `DECIMAL` untuk uang, integer non-negatif untuk jumlah.
- Jangan menambahkan foreign key antartabel bisnis jika relasi bisnis belum ditentukan; tabel yang disediakan sebagian besar berdiri sendiri.
- Gunakan migration Laravel sebagai sumber kebenaran skema. Jangan membuat skema manual yang berbeda di phpMyAdmin.
- Nama tabel autentikasi Laravel adalah `users` (jamak), meskipun istilah menu UI adalah “Data User”.

## 2. Rancangan Tabel

### 2.1 `users`
| Kolom | Tipe yang disarankan | Aturan |
|---|---|---|
| id | BIGINT UNSIGNED PK AI | Primary key |
| nama | VARCHAR(150) | Required |
| username | VARCHAR(80) | Required, UNIQUE |
| password | VARCHAR(255) | Hash, required |
| role | ENUM('admin','user') atau VARCHAR dengan validasi | Required, default `user`; pilih satu pendekatan konsisten |
| foto | VARCHAR(2048) nullable | Path relatif Storage, bukan binary |
| terakhir_login | DATETIME nullable | Diisi setelah login sukses |
| created_at / updated_at | TIMESTAMP nullable | Laravel timestamps |

**Catatan:** Laravel auth provider memakai model `User` dan tabel `users`. Pastikan password field dikenali sebagai password auth dan `foto` tidak dikirim bersama hash password melalui props Inertia.

## 3. Relasi dan Keunikan
- Tidak ada foreign key antara `wna`, `abg`, dan `affidavit` hanya karena kolom paspor/nama mirip; satu orang mungkin punya beberapa jenis catatan dan aturan relasinya belum ditentukan.
- `users.username` wajib unik.
- `settings.key` wajib unik.
- `realisasi_pnpb.bulan` wajib unik agar satu bulan tidak tercatat lebih dari sekali.
- Keunikan `no_register` di tabel WNA/ABG/Affidavit perlu dikonfirmasi sebelum migrasi jika data historis dapat mengandung duplikasi.
- Keunikan `no_paspor` jangan diasumsikan global sebelum aturan bisnis disepakati.

## 4. Validasi
- Batasi panjang string sesuai skema.
- Normalisasi string identifier (trim whitespace) tetapi jangan mengubah kapitalisasi nomor paspor secara destruktif tanpa aturan.
- Validasi tanggal kalender.
- `jenis_izin_tinggal`: hanya `ITAS`, `ITAP`, `VOA`.
- `role`: hanya `admin`, `user`.
- `jenis_kelamin`: pilih nilai internal yang konsisten (rekomendasi `L`/`P`) dan tampilkan label yang mudah dipahami.
- Jumlah laporan izin tinggal harus integer non-negatif.
- Nilai target/realisasi PNBP tidak boleh negatif.
- Upload foto harus memiliki MIME dan ukuran yang diizinkan.

## 5. Index yang Direkomendasikan
Buat index untuk kolom yang sering digunakan dalam pencarian, filter, sorting, dan early warning. Hindari index berlebihan. Untuk early warning, index `wna.masa_berlaku`; untuk list, evaluasi index gabungan berdasarkan query nyata setelah implementasi.

## 6. Seeder dan Data Uji
- Seeder membuat akun admin awal hanya melalui environment/config yang aman atau kredensial lokal yang jelas ditandai untuk development.
- Jangan menaruh password produksi di repository.
- Gunakan factory/seeder dengan data sintetis, bukan data WNA nyata.
- Dokumentasikan cara mengganti kredensial admin awal.
- Test harus membuat data secara terisolasi dan tidak mengandalkan database produksi.
