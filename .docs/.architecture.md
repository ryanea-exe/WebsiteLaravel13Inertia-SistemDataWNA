# Architecture — Sistem Data WNA

## 1. Tujuan
Dokumen ini menetapkan arsitektur aplikasi agar AI agent membangun sistem secara bertahap, konsisten, aman, dan mudah dirawat.

## 2. Stack dan Pola Arsitektur
- **Backend:** Laravel 13, PHP versi yang didukung Laravel 13.
- **Application bridge:** Inertia.js.
- **Frontend:** Vue 3 Composition API, TypeScript, Vite.
- **Styling:** Tailwind CSS.
- **Database:** MySQL.
- **Authentication:** session-based authentication Laravel, bukan token API tanpa kebutuhan.
- **Charts:** pilih library Vue yang aktif dipelihara dan kompatibel, misalnya Chart.js melalui wrapper Vue atau ECharts. Verifikasi kompatibilitas sebelum memasang.
- **Icons:** Lucide Vue atau satu library ikon konsisten.
- **PDF:** pilih package PDF yang kompatibel dengan PHP/Laravel proyek dan uji di lingkungan target.

Gunakan arsitektur **monolith Laravel + Inertia**: backend dan frontend berada dalam satu repositori dan satu aplikasi. Jangan membuat REST API terpisah kecuali kebutuhan baru mengharuskannya.

## 3. Struktur Lapisan

### Backend
- `routes/web.php`: route web dengan middleware auth dan role.
- `app/Http/Controllers/`: controller untuk halaman dan aksi tiap modul.
- `app/Http/Requests/`: Form Request untuk validasi create/update/profile/settings.
- `app/Models/`: Eloquent models, casts, fillable/guarded, dan relasi.
- `app/Policies/` atau gates: otorisasi tindakan berdasarkan role.
- `app/Services/`: logika bisnis yang cukup kompleks, seperti pembuatan PDF atau perhitungan ringkasan dashboard bila membantu.
- `resources/views/app.blade.php`: root Inertia.
- `database/migrations/`, `database/seeders/`, `database/factories/`: skema dan data uji.

Controller harus tipis: validasi melalui Form Request, otorisasi melalui middleware/policy, query efisien, dan response Inertia/redirect yang konsisten.

### Frontend
- `resources/js/app.ts`: bootstrap Inertia + Vue.
- `resources/js/Pages/`: halaman berdasarkan modul, misalnya `Dashboard/Index.vue`, `Wna/Index.vue`, `Abg/Index.vue`.
- `resources/js/Layouts/`: `AuthenticatedLayout.vue`, `GuestLayout.vue`.
- `resources/js/Components/`: komponen reusable seperti `AppSidebar.vue`, `AppHeader.vue`, `AppFooter.vue`, `BaseModal.vue`, `ConfirmDialog.vue`, `DataTable.vue`, `FormField.vue`, `AppButton.vue`, `Toast.vue`, `UserAvatar.vue`, `PageHeader.vue`, dan `StatCard.vue`.
- `resources/js/Composables/`: composables reusable seperti useToast, useDebounce, useClock, dan usePermissions bila memang dibutuhkan.
- `resources/js/types/`: tipe TypeScript untuk user, pagination, table rows, flash messages, settings, dan props halaman.
- Gunakan alias import standar proyek dan pertahankan konsistensi casing nama folder/file.

Ikuti struktur starter kit yang benar-benar dihasilkan oleh instalasi Laravel 13 + Inertia/Vue. Jika nama folder bawaan berbeda, adaptasikan tanpa membuat duplikasi struktur.

## 4. Routing dan Authorization
- Semua halaman privat memakai middleware `auth`.
- Route admin memakai middleware/alias role yang tervalidasi atau policy/gate; pastikan alias middleware diregistrasikan sesuai pola Laravel 13.
- Default setelah login adalah Dashboard.
- User hanya memiliki akses ke Dashboard, WNA read-only + cetak kartu, ABG read-only, Affidavit read-only, Early Warning, dan Edit Profile.
- Jangan hanya menyembunyikan menu atau tombol di Vue. Route, controller action, dan query harus dilindungi server-side.
- Untuk route cetak kartu WNA, pastikan user hanya dapat mencetak kartu untuk data yang boleh dilihatnya.
- Logout harus POST, bukan GET.
- Terapkan rate limiting login dan kebijakan session Laravel.
- Hindari mempercayai `role`, `user_id`, atau izin yang dikirim dari client.

## 5. Alur Request
1. Browser meminta route.
2. Middleware menjalankan autentikasi dan otorisasi.
3. Controller mengambil data melalui Eloquent/query builder dengan pagination server-side.
4. Laravel mengirim page props melalui Inertia.
5. Vue menampilkan UI dan mengirim aksi melalui Inertia router/useForm.
6. Form Request memvalidasi request; policy/gate memverifikasi akses.
7. Laravel menyimpan perubahan; redirect kembali dengan flash message dan error validasi.
8. UI menampilkan toast/status dan mempertahankan input yang aman.

## 6. Pola Data dan Query
- Gunakan Eloquent models dan migration sebagai sumber skema.
- Semua tanggal disimpan sebagai tipe database yang sesuai (`DATE` untuk tanggal kalender; `DATETIME/TIMESTAMP` untuk waktu).
- `masa_berlaku` merupakan tanggal, bukan string bebas.
- `bulan` pada Realisasi PNBP disimpan sebagai `DATE` yang selalu tanggal pertama bulan tersebut, dengan unique index.
- `target` dan `realisasi` menggunakan `DECIMAL`.
- Terapkan index/unique index untuk kolom yang sering dicari dan identifier yang memang harus unik.
- Untuk list, gunakan `paginate()` atau `simplePaginate()`; pertahankan search/filter/sort yang diizinkan dalam query.
- Gunakan allowlist untuk kolom sorting, jangan langsung memakai nama kolom dari request.
- Hindari N+1 query dan hanya kirim props yang diperlukan halaman.
- Gunakan transaksi pada operasi yang melibatkan beberapa perubahan database.

## 7. Upload File
- Validasi foto dengan aturan MIME/jenis file dan ukuran maksimum yang jelas.
- Gunakan nama file acak yang dibuat server; jangan gunakan nama file user sebagai path.
- Simpan pada Laravel Storage disk yang sesuai dan gunakan URL storage yang aman.
- Tangani file lama saat foto diganti; jangan menghapus file yang masih dipakai record lain.
- Jangan menerima executable. Hindari SVG upload mentah kecuali ada sanitasi yang benar.
- Jika upload baru gagal menyimpan record, bersihkan file sementara bila diperlukan.
- Foto boleh kosong dan UI harus memiliki placeholder avatar/foto.

## 8. PDF dan Print
- Pisahkan template PDF dari controller bila perlu.
- Escape semua nilai dinamis dan atur format tanggal serta judul.
- Cetak daftar memakai data terfilter yang konsisten dengan layar; dokumentasikan jika PDF selalu mencetak semua record.
- Kartu WNA individu berisi data ringkasan dan label yang jelas sebagai kartu informasi internal.
- Jangan mengklaim PDF berhasil jika proses render gagal; tampilkan error yang dapat dipahami.
- Verifikasi library PDF terhadap versi PHP dan Laravel aktual proyek sebelum memilihnya.

## 9. UI/UX dan Motion
- Buat design tokens sederhana: warna utama, surface, border, radius, shadow, spacing, dan durasi transisi.
- Gunakan komponen konsisten dan responsive.
- Animasi: sidebar drawer/collapse, dropdown, modal, toast, skeleton, hover, dan transisi halaman ringan.
- Gunakan CSS transition/transform/opacity dan hindari animasi layout berat.
- Hormati `prefers-reduced-motion`.
- Pastikan semua tombol memiliki aksi nyata; tidak boleh ada kontrol dekoratif yang tampak berfungsi tetapi tidak melakukan apa pun.
- Modal harus mendukung Escape, klik overlay bila sesuai, focus management, label, dan validasi.

## 10. Error Handling dan Feedback
- Validasi form menggunakan mekanisme Laravel/Inertia.
- Gunakan flash messages untuk sukses/gagal, dan tampilkan error field di dekat input.
- Bedakan 403, 404, 419/session expired, 422/validation, dan 500 dengan penanganan yang wajar.
- Jangan membocorkan stack trace atau detail internal ke pengguna produksi.
- Gunakan loading state dan cegah double-submit.

## 11. Testing
- Feature tests untuk login, logout, akses role, CRUD, validasi, profil, pengaturan, early warning, dan PDF.
- Test user tidak dapat memanggil endpoint admin secara langsung.
- Unit test untuk logika tanggal early warning dan perhitungan ringkasan bila dipisahkan.
- Frontend build/type-check/lint bila tersedia.
- Jalankan test dan build setelah setiap kelompok fitur besar, bukan hanya di akhir.

## 12. Definition of Done
Sebuah fitur selesai bila:
1. UI responsive dan mengikuti pola desain bersama.
2. Request divalidasi server-side.
3. Authorization ditegakkan server-side.
4. Loading, empty, success, dan error states tersedia.
5. Tipe TypeScript dan props Inertia konsisten.
6. Test relevan lulus.
7. Tidak ada error console/build yang diketahui.
8. Dokumen `.docs` diperbarui jika keputusan arsitektur atau requirement berubah.
