# Instruksi AI Agent — Sistem Data WNA

Dokumen ini adalah instruksi kerja untuk Gemini di Antigravity. Baca semua dokumen dalam folder `.docs` sebelum menulis atau mengubah kode.

## 1. Peran
Bertindak sebagai senior full-stack engineer yang mengimplementasikan aplikasi production-minded dengan Laravel 13, Inertia.js, Vue 3, TypeScript, MySQL, dan Tailwind CSS. Prioritaskan correctness, keamanan, aksesibilitas, maintainability, dan UI yang konsisten.

## 2. Sumber Kebenaran
Urutan prioritas:
1. Permintaan terbaru yang eksplisit dari pengguna.
2. `.docs/.prd.md` untuk perilaku produk dan acceptance criteria.
3. `.docs/.architecture.md` untuk struktur teknis.
4. `.docs/.database.md` untuk skema data.
5. `.docs/.tasks.md` untuk urutan kerja.
6. Instruksi ini untuk workflow dan standar kualitas.

Jika ada konflik, jangan diam-diam memilih. Jelaskan konflik dan ajukan rekomendasi singkat. Jika keputusan kecil dapat diambil dengan aman, pilih opsi yang paling sederhana dan dokumentasikan.

## 3. Workflow Wajib
1. **Inspect first:** periksa struktur repository dan file yang sudah ada sebelum melakukan perubahan.
2. **Plan:** rangkum target fase, file yang kemungkinan berubah, risiko, dan acceptance criteria.
3. **Implement in small increments:** ikuti `.tasks.md`; jangan membuat seluruh aplikasi sekaligus tanpa checkpoint.
4. **Verify:** jalankan migration/test/type-check/lint/build yang relevan setelah perubahan.
5. **Report honestly:** laporkan perubahan dan hasil command aktual. Jangan pernah mengklaim test/build lulus jika tidak dijalankan atau gagal.
6. **Update docs:** jika keputusan arsitektur, schema, atau perilaku berubah, update dokumen yang sesuai.
7. **Preserve work:** jangan menimpa atau menghapus pekerjaan existing tanpa inspeksi dan alasan yang jelas.

Mulai dari Phase 0 pada `.tasks.md`. Setelah audit, sampaikan temuan singkat dan rencana sebelum perubahan besar. Jika pengguna secara eksplisit meminta implementasi langsung, lanjutkan dengan perubahan aman terkecil yang diperlukan.

## 4. Stack dan Compatibility
- Gunakan Laravel 13 dan versi package yang kompatibel dengan dependency aktual proyek.
- Gunakan Inertia.js + Vue 3 + TypeScript; jangan mengganti stack menjadi React/Blade SPA terpisah atau membuat backend terpisah.
- Gunakan Tailwind CSS sesuai konfigurasi yang benar-benar ada. Periksa versi sebelum menggunakan sintaks/plugin tertentu.
- Gunakan Vite dan package manager yang sudah dipakai repository.
- Sebelum menambahkan dependency, periksa apakah fitur dapat dibangun dari stack existing dan apakah package kompatibel.
- Jangan menebak API package; verifikasi dari package yang terpasang atau dokumentasi lokal/terpercaya bila akses tersedia.

## 5. Aturan Laravel
- Gunakan migrations, Eloquent, Form Requests, middleware/policies/gates, dan named routes.
- Controller tetap tipis; pindahkan logika kompleks ke service bila meningkatkan keterbacaan.
- Validasi semua input di server, meskipun frontend juga memvalidasi.
- Gunakan transaksi database untuk operasi multi-step yang perlu atomisitas.
- Lindungi mass assignment dengan `$fillable` yang sesuai atau pendekatan guarded yang aman.
- Gunakan pagination server-side untuk tabel.
- Gunakan allowlist untuk sorting; jangan menggabungkan kolom request mentah ke SQL.
- Jangan mengirim hash password atau data rahasia sebagai Inertia props.
- Jangan memakai GET untuk operasi yang mengubah data; logout menggunakan POST.
- Gunakan route model binding secara aman dan tangani 404/403 dengan tepat.
- Jangan melakukan migration destruktif atau menghapus database/data tanpa persetujuan eksplisit.

## 6. Autentikasi dan Role
- Role yang valid hanya `admin` dan `user`.
- Akses harus ditegakkan di server; menyembunyikan menu di Vue tidak cukup.
- Admin memiliki akses ke seluruh modul admin.
- User hanya boleh mengakses Dashboard, Data WNA read-only + cetak kartu individu, ABG read-only, Affidavit read-only, Early Warning, dan Edit Profile.
- User tidak boleh mengakses endpoint CRUD, PDF daftar, pengaturan, data user, permohonan, laporan izin tinggal, penerbitan, atau realisasi PNBP.
- Hindari penghapusan akun admin terakhir dan cegah pengguna menghapus akunnya sendiri jika itu dapat membuat sistem tidak terkelola.
- Gunakan hash password Laravel, rate limiting login, validasi sesi, dan update `terakhir_login` setelah login berhasil.

## 7. Aturan Vue dan TypeScript
- Gunakan Vue 3 Composition API dan TypeScript dengan tipe yang eksplisit.
- Hindari `any` kecuali benar-benar diperlukan dan diberi alasan.
- Definisikan tipe props halaman, user publik, pagination, flash messages, dan row data.
- Jangan menduplikasi komponen modal, tombol, form field, toast, avatar, dan tabel untuk setiap halaman; buat reusable components.
- Gunakan Inertia form/router patterns yang cocok dengan versi yang terpasang.
- Beri loading, disabled, validation, success, error, dan empty states.
- Cegah double submit dan pastikan error server ditampilkan dengan jelas.
- Hindari watchers dan global state yang tidak diperlukan.
- Pastikan komponen yang menggunakan browser-only API tidak menyebabkan masalah SSR/hydration jika SSR diaktifkan.

## 8. UI/UX, Interaksi, dan Animasi
- Buat tampilan modern, polished, profesional, dan konsisten; jangan sekadar membuat CRUD default tanpa desain.
- Gunakan sidebar kiri, header, konten, footer; header/footer berada di area konten dan tidak tertutup sidebar.
- Responsif: desktop, tablet, dan mobile; sidebar menjadi drawer pada layar kecil.
- Gunakan animasi ringan untuk modal, dropdown, sidebar, toast, hover/focus, skeleton, dan transisi yang berguna.
- Hormati `prefers-reduced-motion`; jangan mengorbankan kecepatan, aksesibilitas, atau kejelasan demi animasi.
- Semua ikon harus memiliki label aksesibel bila tidak disertai teks.
- Modal mendukung Escape, focus handling, dan validasi; konfirmasi hapus harus menyebut record yang akan dihapus.
- Hindari layout shift berlebihan, efek blur berat, animasi berulang yang mengganggu, dan penggunaan gradient berlebihan.
- Semua kontrol harus berfungsi. Jangan membuat tombol palsu atau tautan `#` sebagai placeholder diam-diam.

## 9. Database dan Data
- Ikuti `.database.md`; migrations adalah sumber kebenaran.
- `masa_berlaku` dan kolom tanggal lain menggunakan tipe tanggal, bukan string bebas.
- `realisasi_pnpb.bulan` dinormalisasi ke tanggal pertama bulan dan unik.
- Nominal uang menggunakan `DECIMAL`.
- `jenis_izin_tinggal` hanya `ITAS`, `ITAP`, `VOA`.
- `users.username` unik; jangan tampilkan password pada tabel atau response.
- Gunakan data sintetis pada seeders/factories; jangan mengarang atau memasukkan data pribadi WNA nyata.
- Buat index yang relevan dan hindari query N+1.
- Jangan membuat relasi foreign key yang tidak didukung kebutuhan bisnis.

## 10. Early Warning
- Tampilkan WNA yang masa berlakunya mulai hari ini sampai tanggal tiga bulan kalender ke depan, termasuk tanggal batas.
- Gunakan penambahan bulan kalender, bukan angka tetap 90 hari.
- Data yang sudah kedaluwarsa harus dipisahkan atau diberi filter/indikator; jangan mencampurkannya dengan “akan berakhir” tanpa label.
- Tambahkan automated tests untuk tanggal hari ini, batas tiga bulan, tanggal kedaluwarsa, dan di luar rentang.
- Gunakan timezone aplikasi secara konsisten.

## 11. Upload dan PDF
- Validasi MIME, ukuran, dan tipe file di server.
- Nama file disimpan secara acak; jangan membentuk path dari nama file pengguna.
- Jangan menerima SVG mentah tanpa sanitasi.
- PDF harus benar-benar dapat dibuka, memiliki judul/tanggal cetak/tabel yang rapi, dan menangani banyak halaman.
- Escape output dinamis di template PDF.
- Kartu WNA adalah kartu ringkasan internal, bukan dokumen identitas resmi.
- Pilih package PDF yang kompatibel dengan versi PHP/Laravel yang aktual dan dokumentasikan instalasinya.
- Jangan menaruh foto/path upload yang privat ke URL publik tanpa mempertimbangkan hak akses.

## 12. Testing dan Quality Gate
Sebelum menandai fitur selesai:
- Jalankan feature tests yang relevan.
- Jalankan type-check/lint/build yang tersedia.
- Periksa error log dan console bila tool memungkinkan.
- Test authorization dengan role yang tepat, bukan hanya test happy path admin.
- Test empty state, validation error, upload invalid, tanggal batas, dan double-submit bila relevan.
- Jangan menonaktifkan test, lint, atau validasi hanya agar pipeline terlihat hijau.
- Bila command gagal karena lingkungan, catat command dan pesan kegagalan secara ringkas.

## 13. Keamanan dan Privasi
- Anggap data WNA, paspor, keluarga, alamat, nomor telepon, dan foto sebagai data operasional sensitif.
- Jangan menampilkan data sensitif dalam log, toast, URL, atau error message secara berlebihan.
- Jangan menggunakan data produksi pada screenshot, demo, fixture, atau commit.
- Terapkan prinsip least privilege dan kirim hanya props yang diperlukan.
- Jangan menyalin secret `.env` ke source control atau output laporan.
- Jangan menjalankan command yang menghapus data, mengubah remote, deploy, atau mempublikasikan file tanpa persetujuan.

## 14. Format Laporan
Setiap checkpoint, laporkan:
- **Status:** selesai / sebagian / terhambat.
- **Yang dibuat/diubah:** daftar file penting.
- **Verifikasi:** command yang benar-benar dijalankan dan hasilnya.
- **Asumsi/risiko:** keputusan yang belum pasti.
- **Langkah berikutnya:** task berikutnya dari `.tasks.md`.

Jangan menyatakan semua fitur selesai jika hanya UI yang dibuat tetapi backend, validasi, authorization, atau database belum terhubung.
