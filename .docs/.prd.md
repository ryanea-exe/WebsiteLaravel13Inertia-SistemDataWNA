# Product Requirements Document (PRD)
## Sistem Data WNA

- **Nama produk:** Sistem Data WNA
- **Jenis aplikasi:** Internal web application untuk pengelolaan data dan layanan administrasi terkait Warga Negara Asing (WNA).
- **Bahasa UI:** Bahasa Indonesia.
- **Target pengguna:** Admin dan User yang telah memiliki akun.
- **Stack:** Laravel 13, Inertia.js, Vue 3, TypeScript, MySQL, Tailwind CSS.
- **Status dokumen:** Baseline kebutuhan untuk implementasi oleh AI agent. Jika ada konflik, utamakan keamanan, konsistensi data, dan ketentuan akses per role.

## 1. Latar Belakang dan Tujuan
Aplikasi memusatkan data WNA, pendaftaran ABG dan affidavit, pemantauan masa berlaku izin tinggal, serta rekap permohonan, laporan izin tinggal, penerbitan, dan realisasi PNBP dalam satu dashboard. Sistem harus memudahkan pencarian dan pengelolaan data, menampilkan peringatan masa berlaku izin tinggal, serta menghasilkan dokumen PDF yang rapi.

## 2. Peran dan Hak Akses

### Admin
Dapat mengakses Dashboard, Data WNA, Pendaftaran ABG, Pendaftaran Affidavit, Early Warning, Permohonan, Laporan Izin Tinggal, Penerbitan, Realisasi PNBP, Data User, dan Pengaturan. Admin dapat melakukan CRUD pada modul yang dikelola, mencetak laporan/kartu, mengelola akun, dan mengubah nama serta ikon aplikasi.

### User
Dapat mengakses Dashboard, Data WNA, Pendaftaran ABG, Pendaftaran Affidavit, dan Early Warning. User hanya dapat melihat data. Pada Data WNA, User boleh mencetak kartu individu; tidak boleh membuat, mengubah, menghapus, atau mencetak keseluruhan daftar. Pada ABG dan Affidavit, User tidak melihat kolom aksi dan tidak dapat mengubah data.

### Matriks akses

| Pendaftaran ABG | Lihat, tambah, edit, hapus, cetak PDF daftar | Lihat |
| Pendaftaran Affidavit | Lihat, tambah, edit, hapus, cetak PDF daftar | Lihat |
| Early Warning | Lihat | Lihat |
| Permohonan | Lihat, tambah, edit, hapus, cetak PDF | Tidak boleh mengakses |
| Laporan Izin Tinggal | Lihat, tambah, edit, hapus, cetak PDF | Tidak boleh mengakses |
| Penerbitan | Lihat, tambah, edit, hapus, cetak PDF | Tidak boleh mengakses |
| Realisasi PNBP | Lihat, tambah, edit, hapus, cetak PDF | Tidak boleh mengakses |

Enforce access di server melalui middleware, policies/gates, dan validasi request. Menyembunyikan tombol di UI bukan pengamanan yang cukup.

## 3. Navigasi dan Layout
- Halaman login berdiri sendiri dan tidak menampilkan layout aplikasi setelah login.
- Setelah login, gunakan layout dashboard dengan sidebar kiri, header atas, area konten, dan footer.
- Sidebar memiliki ikon dan nama aplikasi di bagian atas, separator pendek, navigasi sesuai role, serta separator dan jam/tanggal real-time di bagian bawah.
- Header menampilkan judul halaman di kiri; di kanan terdapat ikon notifikasi (placeholder, tanpa fitur notifikasi aktif pada tahap awal) dan avatar/nama pengguna dengan dropdown Edit Profile dan Logout.
- Header dan footer mengikuti area konten di sebelah kanan sidebar; tidak boleh tertutup sidebar. Pada layar kecil sidebar berubah menjadi drawer yang dapat dibuka/tutup.
- Footer berisi copyright aplikasi dan tahun berjalan.
- Sidebar menandai menu aktif dan mendukung collapse bila sesuai rancangan.
- Jam dan tanggal menampilkan waktu lokal browser dan diperbarui secara berkala; hindari hydration mismatch pada Inertia/Vue.

## 4. Modul dan Kebutuhan Fungsional

### 4.1 Login
- Login menggunakan username dan password.
- Mendukung role `admin` dan `user`.
- Password di-hash menggunakan mekanisme Laravel; jangan pernah menyimpan atau menampilkan password plaintext.
- Pesan gagal login bersifat umum agar tidak membocorkan apakah username terdaftar.
- Setelah login, redirect ke Dashboard. Logout mengakhiri sesi dan melakukan regenerasi/invalidasi sesi sesuai praktik Laravel.
- Catat `terakhir_login` setelah autentikasi berhasil.

### 4.2 Dashboard
- Tampilkan ringkasan jumlah WNA, ABG, affidavit, serta indikator relevan lainnya.
- Tampilkan statistik visual seperti grafik tren data WNA, distribusi jenis izin tinggal, kewarganegaraan teratas, dan ringkasan early warning.
- Angka dan grafik harus berasal dari query database nyata, bukan data dummy di produksi.
- Gunakan empty state yang informatif bila data belum tersedia.
- Batasi informasi dashboard User pada modul yang memang dapat diaksesnya.

### 4.3 Data WNA
Kolom bisnis: `no_register`, `no_paspor`, `nama`, `jenis_kelamin`, `kewarganegaraan`, `jenis_izin_tinggal`, `izin_tinggal_ke`, `masa_berlaku`, `penjamin`, `alamat_penjamin`, `nomor_telepon`, `foto`.
- Admin dapat melihat daftar, mencari, mengurutkan, memfilter, menambah, mengedit, menghapus, mencetak PDF seluruh data (mengikuti filter bila implementasi mendukung), dan mencetak kartu individu.
- Tambah/Edit menggunakan modal dengan validasi, tombol Batal dan Simpan, indikator proses, serta pesan sukses/gagal.
- Hapus harus meminta konfirmasi dan menjelaskan data yang akan dihapus.
- User hanya dapat melihat daftar dan mencetak kartu individu. Tidak ada kontrol mutasi maupun cetak daftar.
- Kartu individu bergaya kartu identitas, berisi foto, nama, nomor register, nomor paspor, kewarganegaraan, jenis izin tinggal, dan masa berlaku. Jangan menyebutnya sebagai dokumen identitas resmi pemerintah; ini kartu ringkasan internal.
- `jenis_izin_tinggal` hanya menerima `ITAS`, `ITAP`, `VOA`.
- `no_register` dan `no_paspor` perlu aturan keunikan yang disepakati dan diterapkan di validasi serta database.

### 4.4 Pendaftaran ABG
Kolom bisnis: `no_register`, `no_paspor`, `nama`, `tempat_lahir`, `tanggal_lahir`, `jenis_kelamin`, `kewarganegaraan`, `nama_ayah`, `kewarganegaraan_ayah`, `nama_ibu`, `kewarganegaraan_ibu`, `nomor_telepon`, `alamat`, `foto`.
- Admin dapat melihat, mencari, memfilter, menambah, mengedit, menghapus, dan mencetak PDF daftar.
- User hanya dapat melihat daftar.
- Tambah/Edit menggunakan modal dan validasi server-side serta client-side.
- Cetakan PDF memiliki judul, waktu cetak, dan tabel data dengan header berulang bila lintas halaman.

### 4.5 Pendaftaran Affidavit
Kolom bisnis: `no_register`, `no_paspor`, `nama`, `tempat_lahir`, `tanggal_lahir`, `jenis_kelamin`, `kewarganegaraan`, `masa_berlaku`, `nama_ayah`, `kewarganegaraan_ayah`, `nama_ibu`, `kewarganegaraan_ibu`, `nomor_telepon`, `alamat`, `foto`.
- Hak akses dan pola interaksi sama dengan Pendaftaran ABG.
- Validasi `masa_berlaku` sebagai tanggal yang valid.

### 4.6 Early Warning
- Sumber data adalah tabel WNA.
- Tampilkan WNA dengan `masa_berlaku` dari tanggal hari ini sampai dengan tiga bulan ke depan, termasuk tanggal batas.
- WNA yang sudah kedaluwarsa tidak masuk daftar “akan berakhir” utama; tampilkan indikator/opsi filter terpisah bila disepakati, agar data kedaluwarsa tidak hilang dari pemantauan.
- Tampilkan sisa hari, badge tingkat urgensi, pencarian dan filter.
- Hitung berdasarkan tanggal aplikasi/database dengan zona waktu yang konsisten. Gunakan tanggal kalender, bukan perkiraan 90 hari.
- Data tidak disalin ke tabel baru; hitung dari tabel WNA.

### 4.7 Permohonan
Kolom bisnis: `no_paspor`, `nama`, `kewarganegaraan`, `layanan`, `tanggal`, `kabupaten`, `permohonan`.
- Admin dapat melihat, mencari, memfilter, menambah, mengedit, menghapus, dan mencetak PDF.
- Validasi tanggal dan kolom wajib; teks `permohonan` boleh berupa teks panjang.

### 4.8 Laporan Izin Tinggal
Kolom bisnis: `kategori`, `layanan`, `disetujui_l`, `disetujui_p`, `ditolak_l`, `ditolak_p`, `keterangan`.
- Admin dapat CRUD dan mencetak PDF.
- Kolom jumlah gender disimpan sebagai integer non-negatif dengan default 0.
- Pastikan label UI menjelaskan arti singkatan L/P.
- Pertimbangkan filter kategori/layanan dan ringkasan total yang dihitung dari data.

### 4.9 Penerbitan
Kolom bisnis: `no_paspor`, `nama`, `kewarganegaraan`, `layanan`, `tanggal`, `kabupaten`, `keterangan`.
- Admin dapat CRUD dan mencetak PDF.

### 4.10 Realisasi PNBP
Kolom bisnis: `bulan`, `target`, `realisasi`, `keterangan`.
- Admin dapat CRUD dan mencetak PDF.
- `bulan` direpresentasikan konsisten sebagai tanggal awal bulan (`DATE`) atau pasangan tahun-bulan; rekomendasi: simpan `bulan` sebagai `DATE` dengan tanggal selalu hari pertama dan unique index untuk mencegah duplikasi bulan.
- `target` dan `realisasi` memakai `DECIMAL`, bukan float; validasi non-negatif.
- Dashboard dapat menampilkan rasio realisasi terhadap target bila target lebih besar dari nol.

### 4.11 Data User
- Admin dapat melihat, menambah, mengedit, dan menghapus akun.
- Kolom tabel: foto bulat dan nama, username, role, terakhir login, aksi. Password tidak pernah ditampilkan.
- Modal tambah/edit menggunakan validasi. Password wajib saat tambah; saat edit boleh kosong untuk mempertahankan password lama.
- Cegah admin menghapus akun sendiri atau menurunkan role akun terakhir admin aktif tanpa mekanisme pemulihan.
- `username` unik; role hanya `admin` atau `user`.

### 4.12 Pengaturan
- Admin dapat mengubah nama aplikasi dan ikon aplikasi.
- Simpan dalam tabel pengaturan key/value atau tabel konfigurasi tunggal yang tervalidasi.
- Ikon dapat berupa upload gambar/ikon yang aman; validasi MIME, ukuran, dimensi, dan simpan pada storage publik yang benar. Jangan menerima SVG mentah tanpa sanitasi.
- Pengaturan nama/ikon tercermin pada sidebar, login, title, dan cetakan yang relevan.

### 4.13 Edit Profile
- Pengguna dapat mengubah nama, username (unik), foto, dan password sendiri.
- Field password baru dan konfirmasi password harus sama-sama diisi bila pengguna ingin mengganti password.
- Jika password baru dan konfirmasi kosong, password lama tetap digunakan.
- Wajib meminta password saat ini untuk perubahan password bila praktik autentikasi yang digunakan mendukungnya.
- Validasi upload foto dan berikan preview sebelum simpan.

## 5. Persyaratan UI/UX
- Desain modern, profesional, konsisten, dan terasa interaktif; gunakan Tailwind CSS dan komponen Vue yang reusable.
- Rekomendasi visual: sidebar gelap/navy, area konten terang, aksen biru/indigo, border lembut, radius konsisten, shadow halus, tipografi jelas. Hindari terlalu banyak gradasi dan dekorasi.
- Animasi bermakna: transisi sidebar/drawer, hover/focus states, modal enter/leave, dropdown, skeleton/loading state, toast, chart entrance bila library mendukung, dan micro-interactions tombol.
- Hormati `prefers-reduced-motion`; animasi tidak boleh menghambat input atau aksesibilitas.
- Responsive desktop/tablet/mobile; tabel pada mobile dapat memakai overflow horizontal atau tampilan ringkas tanpa menghilangkan fungsi.
- Semua form memiliki label, pesan validasi dekat field, status loading, dan penanganan error.
- Gunakan ikon dari satu library yang konsisten (misalnya Lucide Vue).
- Pastikan kontras, keyboard navigation, focus ring, aria-label untuk ikon tanpa teks, dan modal dapat ditutup dengan Escape serta mengembalikan fokus.
- Jangan menambahkan fitur visual yang tidak bekerja atau data statistik palsu.

## 6. Pencarian, Tabel, dan Cetak
- Tabel menggunakan pagination server-side, pencarian, sorting, dan filter yang relevan.
- Jangan mengambil seluruh dataset besar ke browser hanya untuk melakukan pagination.
- Gunakan query string untuk filter/pagination bila sesuai agar URL dapat dibagikan.
- Cetak PDF harus benar-benar menghasilkan PDF, bukan hanya tombol dekoratif. Gunakan package Laravel yang kompatibel dengan versi proyek, lalu dokumentasikan instalasinya. Jika package PDF tidak tersedia/kompatibel, jelaskan dan gunakan opsi implementasi yang disetujui, bukan berpura-pura berhasil.
- PDF harus memiliki judul, tanggal/waktu cetak, tabel yang terbaca, nomor halaman jika didukung, dan penanganan tabel panjang.
- Pastikan nilai user tidak disisipkan ke HTML PDF tanpa escaping.

## 7. Non-functional Requirements
- **Security:** CSRF protection, validasi server-side, output escaping, authorization per endpoint, session security, rate limiting login, file upload validation, mass-assignment protection, dan jangan mengirim hash password ke frontend.
- **Privacy:** data WNA dan dokumen foto merupakan data sensitif operasional. Batasi akses sesuai role, jangan tampilkan data pribadi berlebihan di log, dan jangan gunakan data nyata di seed/demo.
- **Reliability:** transaksi database untuk operasi multi-langkah, foreign key/index yang sesuai, error handling konsisten.
- **Performance:** eager loading bila diperlukan, indeks pada kolom pencarian/filter, pagination server-side, hindari N+1 query.
- **Maintainability:** controller tipis, Form Request, policy/gate, service bila ada logika bisnis, reusable Vue components, TypeScript types yang jelas.
- **Localization:** UI Bahasa Indonesia, format tanggal Indonesia dan nominal Rupiah bila relevan.
- **Accessibility:** label, kontras, fokus keyboard, reduced motion.

## 8. Kriteria Penerimaan Utama
1. Login/logout berfungsi dan role dibatasi di server.
2. User tidak dapat melakukan mutasi melalui URL/request langsung.
3. CRUD semua modul admin berfungsi dengan validasi dan notifikasi.
4. User dapat membaca modul yang diizinkan dan mencetak kartu individu WNA.
5. Early Warning menampilkan data dengan tanggal berlaku dalam rentang hari ini sampai tiga bulan ke depan.
6. Dashboard menampilkan statistik dari database.
7. PDF daftar dan kartu WNA menghasilkan dokumen yang dapat dibuka dan dicetak.
8. Foto profil/foto data dapat diunggah dengan validasi, ditampilkan, dan ditangani ketika kosong.
9. Pengaturan nama/ikon tampil konsisten.
10. Form password edit profile mempertahankan password lama jika dua field password kosong.
11. Layout responsive, modal dapat diakses keyboard, dan animasi menghormati reduced motion.
12. Test otomatis mencakup autentikasi, authorization, validasi, CRUD, early warning, dan output PDF utama.

## 9. Asumsi dan Keputusan yang Perlu Dipertahankan
- Gunakan nama tabel database snake_case sesuai daftar kebutuhan.
- Tabel `users` Laravel tetap digunakan untuk autentikasi; nama konseptualnya “user” pada UI.
- Semua tabel bisnis menggunakan `id` auto-increment dan `created_at`/`updated_at` kecuali tabel konfigurasi jika pola lain lebih sesuai.
- Belum ada kebutuhan audit log, notifikasi aktif, multi-cabang, atau workflow approval; jangan menambahkannya tanpa kebutuhan.
- Gunakan soft delete hanya bila kebutuhan retensi/pemulihan disepakati. Jika tidak, gunakan hapus permanen dengan konfirmasi.
- Sebelum mengubah skema atau perilaku yang sudah disetujui, update dokumen terkait dan jelaskan alasan perubahan.
